MODULAR ARCHITECTURE

          
สถาปัตยกรรม 6 โมดูลหลักที่แยกส่วนชัดเจนและตรวจสอบได้จริง

          

            ออกแบบด้วยหลักการ Secure by Design และ Defense in Depth โดยแยกชั้นการรับข้อมูล การตรวจจับ การจัดการเหตุการณ์ และโมดูลคุ้มครอง Release ออกจากกันอย่างอิสระ
          

        


        

          

            

              
MODULE 01 · sentinel_x/ingestion/

              
Multi-Format Log Ingestion & UDP Syslog

              
รองรับการอ่าน แปลง และจัดหมวดหมู่ข้อมูล Log หลายรูปแบบ พร้อมเซิร์ฟเวอร์รับ Syslog แบบ Real-time ผ่าน UDP

            

            
    
              
  • รองรับ JSON, Syslog RFC3164/ISO, Linux Auth/SSH/Sudo, Apache/Nginx Access Logs
    • 
              
  • ทำ Event Correlation ตาม source_ip, user, หรือ source_host
    • 
              
  • ป้องกัน Path Traversal ด้วย Path.resolve() และจำกัดขนาดไฟล์สูงสุด
    • 
            

          


          

            

              
MODULE 02 · sentinel_x/detection/

              
MITRE ATT&CK & Sigma Rule Engine

              
ประมวลผลกฎตรวจจับทั้งแบบเหตุการณ์เดี่ยว (Single-event) และแบบนับความถี่ตามช่วงเวลา (Time-window Correlation)

            

            
    
              
  • ตรวจสอบความถูกต้องกับฐานข้อมูลทางการของ MITRE ATT&CK (Technique ID & Tactic)
    • 
              
  • นำเข้ากฎมาตรฐาน Sigma YAML พร้อมตัวแปร Fallback แบบ Pure-Python
    • 
              
  • แนบคำอธิบายสาเหตุ (Explanation) และหลักฐาน (Event Evidence) ทุก Alert
    • 
            

          


          

            

              
MODULE 03 · sentinel_x/incidents/ & reporting/

              
Incident Response & Multi-Format Reporting

              
บริหารจัดการวงจรชีวิตของ Incident ตั้งแต่การเปิดเคส บันทึกการสอบสวน ผูกหลักฐาน ไปจนถึงการส่งออกรายงาน

            

            
    
              
  • สถานะมาตรฐาน OPEN, INVESTIGATING, CONTAINED, RESOLVED, CLOSED
    • 
              
  • สร้าง Incident Timeline อัตโนมัติพร้อมบันทึกลง Security Audit Log
    • 
              
  • ส่งออกรายงานเป็น JSON, Markdown, และ HTML (ป้องกัน XSS ทุกจุด)
    • 
            

          


          

            

              
MODULE 04 · sentinel_x/dashboard/

              
Local-First SOC Dashboard & REST API

              
เว็บอินเทอร์เฟซและ REST API แบบ Multi-threaded ที่ดึงข้อมูลจริงจากฐานข้อมูล SQLite ท้องถิ่นโดยตรง

            

            
    
              
  • แยกข้อมูลจริง (REAL) ออกจากข้อมูลตัวอย่าง (SAMPLE) อย่างโปร่งใส
    • 
              
  • รองรับการยืนยันตัวตน API ด้วย SENTINEL_API_TOKEN แบบ Constant-time (hmac.compare_digest)
    • 
              
  • ใช้ Parameterized SQL Queries 100% เพื่อป้องกัน SQL Injection

ANTI-REA · RELEASE PROTECTION ARCHITECTURE

          
การยืนยันความสมบูรณ์ของซอฟต์แวร์ด้วยลายเซ็นดิจิทัล Ed25519 และการป้องกันการดัดแปลงไฟล์

          

            ไม่มีซอฟต์แวร์ใดสามารถรับประกันการป้องกัน Reverse Engineering ได้ 100% โมดูล Anti-REA ของ Sentinel-X จึงมุ่งเน้นมาตรการทางวิศวกรรมที่พิสูจน์ผลได้จริง ได้แก่ การตรวจจับการแก้ไขไฟล์โดยไม่ได้รับอนุญาต (Tamper Detection), การลงนาม Release Manifest ด้วยกุญแจภายนอก และการสแกนป้องกันข้อมูลความลับรั่วไหลก่อนเผยแพร่
          

        


        

          

            
1. Pre-Release Security Audit

            
สแกนทุกไฟล์ในโปรเจกต์เพื่อตรวจหา Hardcoded Secrets, ไฟล์กุญแจ .pem/.key, .env, Debug Artifacts, Source Maps และคำสั่ง shell=True

            
python3 -m sentinel_x.security.release_protection.cli audit --root . --format markdown

          


          

            
2. RFC 8032 Ed25519 Manifest Signing

            
คำนวณ SHA-256 ของทุกไฟล์ใน Release และลงนามดิจิทัลด้วยกุญแจส่วนตัวที่เก็บไว้นอก Repository (เข้ากันได้กับ OpenSSL 3.0 100%)

            
python3 -m sentinel_x.security.release_protection.cli sign --root . --private-key /path/to/rel.key --output release_manifest.json

          


          

            
3. Tamper Detection & Verification

            
ตรวจสอบทั้งลายเซ็นดิจิทัล Ed25519 และค่า SHA-256 ของทุกไฟล์ หากไฟล์ถูกแก้ไข ลบ หรือเพิ่มเข้ามาโดยไม่ได้รับอนุญาต ระบบจะแจ้งเตือนทันที

            
python3 -m sentinel_x.security.release_protection.cli verify --root . --manifest release_manifest.json --public-key /path/to/rel_public.pem
