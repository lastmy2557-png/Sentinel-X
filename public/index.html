              MITRE ATT&CK rule & time-window correlation

            05
            
Security & Anti-REA Release Protection

          

          

            มาตรการป้องกันทางวิศวกรรมของ Sentinel-X ถูกบังคับใช้ตั้งแต่ก่อนคอมไพล์ไฟล์ sentinel-x.exe ไปจนถึงการตรวจสอบลายเซ็นดิจิทัลปลายทาง:
          


          
          
    
            
  • 
              The signed manifest (RFC 8032 Ed25519). ทุกไฟล์ในชุด Release ถูกคำนวณค่า SHA-256 และลงนามด้วยกุญแจ Ed25519 ที่เก็บไว้นอก Repository หากไฟล์ถูกดัดแปลงแม้แต่ไบต์เดียว การตรวจสอบจะล้มเหลวทันที (TAMPER_DETECTED)
            
    • 
            
  • 
              Pre-build secret & artifact scanner. ก่อนสร้างไฟล์ .exe หรือ .patch ระบบจะสแกนหา AWS/GitHub/Slack Tokens, Private Keys (.key, .pem), ไฟล์ .env, pdb.set_trace() และ shell=True
            
    • 
            
  • 
              Parameterized SQL & masked credentials. ชั้นฐานข้อมูล SQLite ใช้ Parameterized Queries (?) 100% และหน้าตั้งค่า API จะแปลงรหัสลับทุกตัวเป็น ••••••••xxxx ก่อนส่งกลับเสมอ
            
    • 
            
  • 
              Honest engineering boundary. ไม่มีซอฟต์แวร์ใดป้องกันการทำ Reverse Engineering ได้ 100% ระบบ Anti-REA จึงมุ่งเน้นการทำ Tamper Detection, Release Integrity Verification และการลดการเปิดเผยข้อมูลอ่อนไหวที่พิสูจน์ผลได้จริง
